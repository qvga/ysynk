## ysynk 0.5.5

**Cancel operation now targets the job shown in the activity bar.** If that job finishes and a scheduled backup starts before your click reaches the engine, the new backup continues. The button shows when cancellation is requested and lets you retry if the request fails.

### Backups and restores

- A backup stays marked as running while ysynk collects destination results. Operation history publishes the final outcome and destination summary together and identifies the profile or repository when available.
- Snapshots appear newest first. When the configuration changes during a snapshot or directory lookup, the browser discards errors from the old selection.
- Switching retention profiles clears the previous deletion preview and preserves repository statistics and checks that are still loading.
- At startup, ysynk checks that the configured executable identifies itself as restic and reports a supported version.
- The Linux build includes the upstream `url` 2.5.9 fix for a stack overflow in URL origin handling. [RustSec advisory](https://rustsec.org/advisories/RUSTSEC-2026-0592.html)

The [user guide](https://github.com/qvga/ysynk/blob/v0.5.5/docs/guide.md) covers setup and recovery. Contributors can trace each workflow to the code and tests that own it in the [state-machine map](https://github.com/qvga/ysynk/blob/v0.5.5/docs/state-machines.md).

### Linux x86-64 downloads

- `ysynk_0.5.5_amd64.deb` for Debian and Ubuntu.
- `ysynk-0.5.5-linux-x86_64.tar.gz` for manual installation, with a launcher helper and licenses.
- `SHA256SUMS` for both packages. From the download directory, run `sha256sum --ignore-missing --check SHA256SUMS` and check that your chosen package is listed as `OK`.

Both packages require restic 0.17.1 or newer, GTK3, WebKitGTK 4.1, AppIndicator and a persistent Secret Service keychain. The binary assets are unsigned.
