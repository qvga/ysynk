# State machines in ysynk

This map covers first-party runtime behavior in the Rust core, desktop shell and Svelte renderer. Each row groups states that share an owner and an event that moves them forward. A single job can participate in several rows. For example, closing a restore dialog changes focus and discards the form while the core continues restoring files.

## Follow one job

| Event | What becomes observable |
| --- | --- |
| A manual request or scheduler tick wins admission | The core records the active job and its ID before starting a worker. A failed admission write blocks further work until restart. |
| The activity bar offers Cancel for job A | The renderer sends `cancel_job` with A's ID. The core compares it to the active ID under the same lock used for admission and completion. An absent or different job yields an error. The legacy `cancel` request still targets whichever job is current. |
| Cancellation is accepted | The request returns `null`. The control stays disabled for A while the worker drains. A replacement job gets its own control. History supplies the final outcome. |
| The worker finishes | The core sets the finish time and outcome and moves the job from active to history under one lock. A backup's destination results accumulate during execution. Its aggregate outcome first appears in history. |
| A caller awaits a result | Only a poll **started after admission returned** can settle the wait. A terminal history entry resolves it. Absence from both active and history rejects it. A lost connection leaves the wait pending for reconnection. |

Trace this path in [App::request and App::complete](../crates/core/src/runtime.rs), the [activity bar](../ui/src/App.svelte) and [JobCompletions](../ui/src/lib/jobs.ts).

## Engine and repository operations

| Workflow and owner | States, events and guards |
| --- | --- |
| Startup and recovery · [App::open_inner](../crates/core/src/runtime.rs) | Acquire the data-directory lock → validate configuration → load journal → probe restic. An active entry left on disk becomes an interrupted history entry. An unusable executable leaves Settings accessible. |
| Engine selection and configuration · [set_restic_executable, save_config](../crates/core/src/runtime.rs) | Native picker cancellation ends the edit. A selection is validated against the current revision. An accepted save increments the revision and invalidates previews. A changed executable requires a restart and version probe. Repository IDs retain their exact location binding. |
| Durable writes · [persist, persistence_failed](../crates/core/src/runtime.rs), [config::write](../crates/core/src/config.rs) | A save, admission or completion can fail before or after publication on disk. Failure blocks further mutation and scheduling. Failed admission restores prior attempts in memory. Failed completion retains the outcome for inspection. Reopening reconciles from disk. |
| Admission and shutdown · [ensure_idle, request_locked, shutdown](../crates/core/src/runtime.rs) | Idle → one active job or password export → idle. Shutdown closes admission, signals cancellation, joins workers and waits for a reserved export. Status reads and cancellation have their own admission paths. |
| Scheduling · [due_profile, tick](../crates/core/src/runtime.rs) | Manual-only or waiting → due → admitted → next interval. An idle, usable engine chooses the oldest eligible deadline. Backup admission and completion both record attempts, including manual backups and failed runs. |
| Backup fan-out · [backup, complete](../crates/core/src/runtime.rs) | Destinations run in profile order. Exit 0 records success, exit 3 records incomplete data, and other errors record failure. All successes yield success, any useful but incomplete backup yields partial, and all failures yield failed. Cancellation takes precedence and keeps recorded destination evidence. |
| Job history and results · [complete, journal_entry](../crates/core/src/runtime.rs) | Active → terminal → retained → evicted after 100 entries. The session result budget can discard a query payload while the job is still visible. The journal stores metadata and destination results. Query payloads and console tails stay in memory. |
| Keychain and initialization · [credentials::read, creation_lock](../crates/core/src/credentials.rs), [perform](../crates/core/src/runtime.rs) | Missing → create once under a per-repository lock → reread the bound credential and probe. A successful probe reconnects. Only a missing-repository response (exit 10) permits initialization. Locked, invalid or unavailable credentials stop the attempt. Retry reads the existing record, including after an uncertain create. |
| Subprocess lifetime · [restic::run_inner](../crates/core/src/restic.rs) | Start → stream progress/output → exit and drain pipes → join. Cancellation, overflow or timeout interrupts the child. On Unix a grace period precedes a forced kill and the post-exit drain is bounded. |
| Output and progress · [reader, backup_reader](../crates/core/src/restic.rs), [console::Records and Tail](../crates/core/src/console.rs) | Queries collect bounded raw results. Backup status updates progress and a summary supplies counts. Console records accumulate until newline or EOF. An oversized console record is skipped through its boundary. Redacted display lines enter a bounded tail with a truncation flag. |
| Repository inspection · [query, perform](../crates/core/src/runtime.rs) | Statistics and snapshot queries return parsed results. A directory query returns immediate children of the requested path. Check streams diagnostics and produces a terminal job. Each follows normal job admission and cancellation. |
| Retention and pruning · [preview, apply_retention, perform](../crates/core/src/runtime.rs) | A successful dry run replaces the previous token. The token expires after five minutes and is tied to the config revision and repository identity. After `DELETE`, apply consumes it before revalidating candidates, survivors and tags. A retry needs a fresh preview. Repository-wide prune has a separate `PRUNE` confirmation. |
| Restore output · [restore](../crates/core/src/runtime.rs), [private_restore_directory](../crates/core/src/runtime/destination.rs) | Validate the literal selection and obtain its credential → create a fresh private target → restore with verification. Failure or cancellation after creation leaves the target for inspection. A retry requires a new target. |
| Password export · [export_repository_password](../crates/core/src/runtime.rs), [destination checks](../crates/core/src/runtime/destination.rs) | After native file selection, reserve admission → validate and pin target parent → stage private file → publish exclusively → sync parent. A late sync error reports uncertain durability and preserves the published file. Dropping the reservation wakes shutdown. |

The [request and recovery tests](../crates/core/src/tests.rs), [runtime tests](../crates/core/src/runtime_tests.rs) and [subprocess tests](../crates/core/src/restic_tests.rs) exercise these transitions with temporary directories, injected failures and restic processes.

## Renderer workflows

| Workflow and owner | States, events and guards |
| --- | --- |
| Engine connection · [refresh, accept](../ui/src/App.svelte) | Connecting → connected or unavailable → retry. One poll runs at a time. A successful configuration write advances a generation so an older response cannot replace it. Cached status can remain visible during disconnection. Executable readiness and connection health are separate. |
| Operation controls · [run, save, selectEngine](../ui/src/App.svelte), [JobCompletions](../ui/src/lib/jobs.ts) | Submission, a pending completion, an observed active job or a connection error blocks competing actions. Fast completions can appear directly in history. Unmount rejects outstanding waits. |
| Cancellation control · [CancelOperation](../ui/src/lib/CancelOperation.svelte) | Idle → sending → requested, or failed with retry. Both sending and requested disable the button. The activity bar keys the control by job ID, so a late acknowledgement or error belongs to the original job. |
| Navigation, feedback and theme · [navigate, action, setTheme](../ui/src/App.svelte) | Profiles, Repositories, Snapshots and Settings each mount their own view. Navigation clears page feedback and focuses main content. Operations can continue across navigation. Theme selects system, light or dark and restores a stored choice on mount. |
| Editors · [Profiles](../ui/src/lib/Profiles.svelte), [Repositories](../ui/src/lib/Repositories.svelte) | Closed → new or existing draft → validating/saving → closed on success or editable with an error. Drafts carry the original config revision. A referenced repository must be removed from its profiles before its configuration can be removed. Initialize/retry captures a repository for confirmation before submission. |
| Inspection and maintenance dialog · [tools, query, maintenance](../ui/src/lib/Repositories.svelte) | Open for a repository → running → result/error. Closing discards the dialog's interest in the result. Statistics and check belong to a repository and revision. Changing the retention profile invalidates the preview request and confirmation, including when switching away and back. |
| Retention and prune confirmations · [apply, prune](../ui/src/lib/Repositories.svelte) | Preview → review candidates → type `DELETE` → submit once or re-preview after expiry. A profile change clears the displayed preview. Prune uses its own confirmation and can run independently of preview. Native checks govern both operations. |
| Snapshot list and file browser · [load, choose, browse, toggle](../ui/src/lib/Snapshots.svelte) | Select repository → load → empty/list/error → choose snapshot → open directory → empty/entries/error. Request tickets and scope guard late replies. Path selection survives browsing directories in one snapshot and clears on a new snapshot or repository. |
| Restore dialog · [openRestore, submitRestore](../ui/src/lib/Snapshots.svelte) | Capture snapshot, scope and paths → enter new target → submit → verified or failed/cancelled. The dialog can close while the job runs. The activity bar retains cancellation, and failures identify where incomplete output may remain. |
| Modal focus · [Dialog](../ui/src/lib/Dialog.svelte) | Open → trap Tab focus → submit or dismiss. Invalid fields open their containing details. On close, focus returns to the trigger if usable, then falls back to a job control, toolbar or main content. Each caller controls whether dismissal is allowed while saving. |
| Live and historical output · [CommandOutput](../ui/src/lib/CommandOutput.svelte), [HistoryOutput](../ui/src/lib/HistoryOutput.svelte) | Active view waits for output, then follows the tail. Scrolling up pauses follow and returning to the bottom resumes it. A new job resets follow. Historical output mounts on expansion and unmounts on collapse. |
| Startup settings editor · [loadDesktop, saveDesktop, confirmTray](../ui/src/lib/Preferences.svelte) | Loading → clean draft → dirty → saving. Enabling hide-to-tray requires acknowledging a visible icon. Start minimized depends on login, hide-to-tray and host availability. Save failure triggers a native reread. A failed reread offers retry. |
| Password export and quit · [exportPassword, quit](../ui/src/lib/Preferences.svelte) | Export captures repository and revision, requires plaintext acknowledgement and opens a native picker. Cancellation returns to the form, failure allows retry, and successful publication closes it. Quit has a separate confirmation and waits for native shutdown. |

The [poll-order tests](../ui/src/lib/jobs.test.ts) cover completion and eviction. The [model](../ui/src/lib/model.test.ts), [navigation](../ui/src/lib/navigation.test.ts) and [output](../ui/src/lib/output.test.ts) tests cover result and view behavior. The [WebKit interaction fixture](../ui/audit-interactions.mjs) drives the bundled UI through actual controls with in-memory IPC.

## Native desktop lifecycle

| Workflow and owner | States, events and guards |
| --- | --- |
| Activation and window visibility · [main, setup, show](../desktop/src/main.rs), [tray](../desktop/src/tray.rs) | A normal second manual launch activates the existing window. A data-directory override uses its own instance lock. A login launch can start hidden when configured to minimize and hide, a host is available and manual reactivation has not intervened. Close hides only if the configured tray is usable and hiding succeeds. Losing the tray host reveals a hidden window. |
| File picker ownership · [FileDialogGuard](../desktop/src/commands.rs) | Available → held by executable picker or password export → released on every return path. Opening a picker leaves core admission available. Selection rechecks shutdown and the core checks revision and admission before committing. |
| Login registration · [settings::Service](../desktop/src/settings.rs) | Load OS registration and preferences → checkpoint → change and verify registration → save preferences → publish runtime settings. A failed change attempts rollback. Reload reconciles both sources. Overrides use disabled login registration. |
| Notifications · [notification_states](../crates/core/src/runtime.rs), [tray::notify](../desktop/src/tray.rs) | Seed cursor at startup → advance across new completions → notify for eligible job kinds in completion order. Old history is skipped at startup. |
| Process exit · [begin_shutdown and ExitRequested](../desktop/src/main.rs) | Running → draining → exit permitted. Repeated quit requests share the transition. Core shutdown drains jobs and exports, then the settings service drains any transaction before exit. |

The [desktop settings tests](../desktop/src/settings_tests.rs) cover startup visibility policy, registration, rollback and serialization. Native picker behavior and tray-host loss also depend on the desktop environment. See the [local verification instructions](../CONTRIBUTING.md#run-the-checks).
